\unnumberedsection{Résumé}
\addcontentsline{toc}{section}{Résumé}

\begin{abstractbox}
Les systèmes de contrôle industriels (ICS) pilotent des procédés physiques dont la compromission peut avoir des conséquences graves en matière de sûreté, d'environnement et d'économie. L'évaluation du risque cyber ne peut se limiter à une liste de vulnérabilités : elle doit intégrer la topologie, les dépendances, les protections, l'incertitude et les observations.

Le présent projet propose un framework qui transforme une architecture ICS en un réseau bayésien discret. Il calcule des probabilités intrinsèques de compromission et paramètre automatiquement les tables de probabilités conditionnelles (CPT) via un modèle Noisy-OR, en attribuant une probabilité de propagation pour chaque relation. L'inférence exacte tient compte des preuves et classe les actifs par risque.

Une application Desktop mono-utilisateur permet d'importer une topologie (JSON, YAML, CSV), de sélectionner des preuves, d'exécuter l'analyse, d'inspecter le réseau et de télécharger un registre des risques ainsi qu'un rapport PDF. Le prototype est fonctionnel, modulaire, testable et configurable pour s'adapter à des contextes industriels réels.
\end{abstractbox}

% ABSTRACT

\newpage
\thispagestyle{empty}
\unnumberedsection{Abstract}
\addcontentsline{toc}{section}{Abstract}

\begin{abstractbox}
Industrial Control Systems (ICS) drive physical processes whose compromise can lead to severe safety, environmental, and economic consequences. Cybersecurity risk assessment cannot be reduced to a mere list of vulnerabilities; it must account for topology, dependencies, protections, uncertainty, and observations.

This project introduces a framework that transforms an ICS architecture into a discrete Bayesian network. It computes intrinsic compromise probabilities and automatically populates Conditional Probability Tables (CPTs) using a Noisy-OR model, assigning a propagation probability to each relationship. Exact inference incorporates evidence and ranks assets by risk.

A single-user desktop application enables users to import a network topology (JSON, YAML, CSV), select evidence, execute the risk analysis, inspect the Bayesian network, and download a risk register along with a PDF report. The prototype is functional, modular, testable, and configurable, allowing it to be adapted to real-world industrial environments.
\end{abstractbox}

\section{Introduction générale}
\markboth{Introduction générale}{Introduction générale}
\forcereset{8}

\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Un ICS regroupe automates (PLC), IHM, serveurs SCADA, capteurs, actionneurs, postes d'ingénierie.
    \item Contrairement à un SI classique, une erreur de commande ou une indisponibilité affecte directement le monde physique.
    \item Les exigences de disponibilité, sûreté et continuité d'exploitation sont primordiales.
    \item Les méthodes classiques (matrice vraisemblance × impact) peinent à modéliser la propagation d'une compromission, l'effet d'un pare-feu ou l'évolution d'un diagnostic à partir d'observations.
    \item Les réseaux bayésiens répondent à cette limite : graphe orienté acyclique, mise à jour des probabilités à partir d'observations.
    \item Le projet conçoit un framework générique, transparent et exploitable par un analyste de risque.
    \item Les chapitres suivants détaillent le besoin, l'architecture, les choix techniques, la chaîne de calcul, l'interface et les perspectives.
\end{itemize}

\section{Présentation du projet}
\markboth{Présentation du projet}{Présentation du projet}

\subsection{Problème et besoin}
\forcereset{5}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Une topologie ICS contient des actifs hétérogènes et des liens de nature variée (programmation, commande, supervision, etc.).
    \item Il faut convertir ces relations en un modèle quantitatif pour répondre à des questions comme :
        \begin{itemize}
            \item « Quelle est la probabilité qu'un automate soit compromis si une HMI l'est ? »
            \item « Quels actifs doivent être traités en priorité ? »
        \end{itemize}
    \item Le framework accepte une topologie structurée, valide ses actifs et relations, puis produit un classement des risques.
    \item Utilisateurs cibles : analystes cybersécurité ICS, ingénieurs OT, responsables de sûreté, encadrants.
    \item Résultat compréhensible sans manipulation directe de code Python.
\end{itemize}

\subsection{Fonctionnalités livrées}
\forcereset{5}
\begin{contributionbox}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip, topsep=2pt]
    \item Modélisation d'actifs humains, techniques et physiques.
    \item Import de topologies JSON, YAML ou CSV + jeux de données prédéfinis.
    \item Pondération des dépendances et des contrôles.
    \item Calcul automatique des probabilités de base, des CPT et des probabilités de propagation.
    \item Inférence bayésienne à partir de preuves « Compromised » ou « Safe ».
    \item Calcul et classement des risques, identification de chemins d'attaque.
    \item Tableau de bord Web avec visualisation de graphe et inspection des CPT.
    \item Export d'un registre de risques CSV et d'un rapport PDF de synthèse.
\end{itemize}
\end{contributionbox}

\section{Workflow de l'application}
\markboth{Workflow de l'application}{Workflow de l'application}
\forcereset{5}

\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Parcours utilisateur en six étapes séquentielles, du chargement de la topologie à l'export des livrables.
    \item Chaque étape correspond à une section du tableau de bord React et à une route de l'API FastAPI.
\end{itemize}

\subsection{Vue d'ensemble du parcours utilisateur}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Au chargement, le frontend récupère les pondérations via GET /settings et affiche un tableau de bord vide.
    \item Choix d'un jeu de données prédéfini (SWAT, Building Automation, Power Substation, Water Treatment) ou import d'un fichier.
    \item L'évaluation n'est possible qu'après chargement d'une topologie (bouton désactivé sinon).
\end{itemize}

\begin{notebox}[Astuce]
Raccourci clavier (touche r) pour lancer l'évaluation une fois les données disponibles.
\end{notebox}

\subsection{Chargement et validation de la topologie}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Deux chemins de chargement :
        \begin{itemize}
            \item GET /datasets/\{nom\} pour un preset, republié via POST /upload-topology.
            \item POST /upload-topology-file pour un fichier .json, .yaml/.yml ou .csv (backend seul parse et valide).
        \end{itemize}
    \item La validation côté serveur vérifie le graphe orienté acyclique et les champs requis par type d'actif.
    \item Changer de preset alors que des preuves existent déclenche une confirmation (réinitialisation de la topologie, des preuves et du résultat).
\end{itemize}

\begin{warningbox}[Gestion des erreurs]
En cas d'échec, le message d'erreur (champ detail de FastAPI) est affiché dans une notification.
\end{warningbox}

\newpage
\subsection{Sélection des preuves et configuration}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Pour chaque actif, l'utilisateur choisit un état : Unknown, Compromised ou Safe.
    \item Les preuves sont conservées côté client sous forme lisible, puis converties en couples \{asset, state\} (valeurs 0/1) à l'envoi.
    \item Le panneau « Settings » permet d'ajuster :
        \begin{itemize}
            \item Poids CVSS, d'exposition, de correctif et d'impact.
            \item Poids de propagation par type de relation (controls, monitors, actuates, connects-to, programs / operates).
            \item Multiplicateurs pour lien pare-feuté ou non.
        \end{itemize}
    \item Ces réglages sont persistés côté serveur (GET/PUT /settings) et s'appliquent à toute évaluation ultérieure.
\end{itemize}

\subsection{Exécution de l'évaluation bayésienne}
\forcereset{5}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Clic sur « Lancer l'évaluation » → envoi de la topologie et des preuves non « Unknown » à POST /analyze.
    \item Le moteur :
        \begin{itemize}
            \item Construit le réseau bayésien.
            \item Calcule les probabilités intrinsèques de chaque actif.
            \item Dérive les CPT selon un modèle Noisy-OR.
            \item Attribue une probabilité de propagation pour chaque relation.
            \item Exécute une inférence exacte (élimination de variables) avec les preuves.
        \end{itemize}
    \item Production :
        \begin{itemize}
            \item Score de risque par actif.
            \item Un ou plusieurs chemins d'attaque candidats, chacun avec un score combinant poids de propagation et risque de la cible.
        \end{itemize}
\end{itemize}

\newpage
\subsection{Exploration des résultats}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Le résultat alimente plusieurs vues synchronisées :
        \begin{itemize}
            \item Graphe interactif (@xyflow/react) positionné par couches BFS, coloré par probabilité postérieure ou type d'actif, avec mise en évidence du chemin d'attaque critique.
            \item Panneau de détails par nœud sélectionné (probabilité intrinsèque, postérieure, rang de risque, appartenance au chemin).
            \item Tableau de bord synthétique : risque global, niveau, top 5 des actifs, chemin prioritaire, liste complète des chemins.
            \item Graphique en barres des probabilités postérieures.
            \item Graphique en secteurs de répartition des niveaux de risque.
            \item Tables de probabilités conditionnelles consultables et filtrables par nom d'actif.
        \end{itemize}
\end{itemize}

\subsection{Export des livrables}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Deux exports disponibles :
        \begin{itemize}
            \item Registre des risques au format CSV (triable, exploitable dans un tableur).
            \item Rapport PDF de synthèse destiné aux décideurs.
        \end{itemize}
    \item Fichiers générés côté serveur à partir du dernier résultat d'analyse.
    \item Accessibles via GET /reports/\{fichier\}.
\end{itemize}

\section{Choix technologiques}
\markboth{Choix technologiques}{Choix technologiques}

\subsection{Frontend}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item React : bibliothèque JavaScript basée sur une architecture en composants permettant la réutilisabilité du code, le rendu dynamique de l'interface utilisateur et la mise à jour des vues sans rechargement complet de la page (Single Page Application).
    \item TypeScript : langage fortement typé permettant de définir explicitement les modèles de données (TopologyPayload, résultats d'inférence, preuves), réduisant ainsi les erreurs de développement et améliorant la maintenabilité du code.
    \item Vite : outil de développement offrant un serveur de développement très rapide grâce au rechargement à chaud (Hot Module Replacement) et une compilation optimisée pour la production.
    \item Tailwind CSS : framework CSS utilitaire permettant de construire rapidement une interface moderne, responsive et homogène tout en limitant la quantité de CSS personnalisé.
    \item @xyflow/react : bibliothèque spécialisée dans la visualisation et la manipulation interactive de graphes, permettant le zoom, le déplacement, la sélection de nœuds et la représentation intuitive de l'architecture ICS.
    \item Recharts : bibliothèque de visualisation utilisée pour représenter graphiquement les probabilités, les distributions de risque et les résultats d'inférence bayésienne.
    \item Appels HTTP : API HTTP native du navigateur utilisée pour communiquer avec le backend FastAPI. Cette solution couvre les besoins du projet sans nécessiter l'ajout d'une bibliothèque externe telle qu'Axios.
\end{itemize}

\newpage
\subsection{Backend et moteur}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Python : langage de programmation choisi pour la richesse de son écosystème scientifique et de ses bibliothèques dédiées à la modélisation probabiliste, au traitement de données et à l'intelligence artificielle.
    \item FastAPI : framework web moderne permettant le développement d'API REST performantes, asynchrones et fortement typées, avec génération automatique de la documentation OpenAPI.
    \item Uvicorn : serveur ASGI léger et performant assurant l'exécution des applications FastAPI.
    \item Pydantic : validation des corps de requête (preuves, topologies) avant appel au moteur + garantit la cohérence des données échangées entre le frontend et le backend.
    \item pgmpy : bibliothèque spécialisée dans les réseaux bayésiens fournissant les structures de données, les tables de probabilités conditionnelles (CPD) ainsi que les algorithmes d'inférence exacte (Variable Elimination), évitant le développement d'un moteur probabiliste complexe.
    \item NetworkX + Matplotlib : utilisés pour construire, manipuler et exporter automatiquement la topologie ICS sous forme graphique.
    \item Pandas : utilisé pour générer les tableaux de résultats, calculer les indicateurs de risque et produire les exports CSV.
    \item NumPy : est utilisé indirectement par plusieurs bibliothèques scientifiques du projet (pgmpy, Pandas, Matplotlib) mais n'est pas exploité directement dans le code métier.
\end{itemize}

\newpage
\subsection{Base de données}
\forcereset{4}
\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item \textbf{SQLite} : moteur de base de données relationnelle embarqué utilisé comme stockage principal du framework. La base est enregistrée dans un fichier unique (\texttt{backend/data/ICSRiskFramework.db}) sans nécessiter de serveur ni de configuration. Ce choix simplifie le déploiement en développement et permet de démarrer l'application immédiatement après le clonage du dépôt.
    \item \textbf{SQLAlchemy 2.0} : ORM (Object-Relational Mapping) complet pour la persistance des analyses en base de données. Il est utilisé avec SQLite en développement et peut basculer vers PostgreSQL en production via la variable d'environnement \texttt{ICS\_DB\_URL}. La version 2.0 utilise le style de déclaration par type (\texttt{Mapped} + \texttt{mapped\_column}) offrant un typage statique des modèles. Un modèle Repository découple l'accès aux données de la couche métier.
    \item \textbf{Alembic} : outil de gestion de migrations de schéma de base de données pour SQLAlchemy. Il permet de versionner les évolutions du schéma (création de tables, ajout de colonnes) via des fichiers de migration générés automatiquement. La migration initiale (\texttt{alembic/versions/3f1fade8e943\_initial\_schema.py}) définit les 9 tables du projet : projets, actifs, connexions, nœuds bayésiens, CPT, résultats d'inférence, scores de risque, rapports et paramètres.
    \item \textbf{Initialisation automatique} : la base et les tables sont créées au premier appel à la fonction \texttt{initialize\_database()}, protégée par un indicateur pour éviter les doublons. Le fichier \texttt{backend/database/config.py} centralise la configuration et permet de changer de moteur (PostgreSQL, MySQL) sans modifier le code applicatif.
\end{itemize}

\section{Conclusion}
\markboth{Conclusion}{Conclusion}
\forcereset{7}

\begin{itemize}[leftmargin=1.2cm, itemsep=0.2\baselineskip]
    \item Le framework démontre qu'une topologie ICS peut être transformée en un réseau bayésien exploitable.
    \item Il permet le calcul des probabilités intrinsèques, le classement des actifs par risque et l'identification de chemins d'attaque plausibles.
    \item L'application Web rend cette chaîne de calcul accessible sans code, avec traçabilité complète :
        \begin{itemize}
            \item Preuves explicites.
            \item Paramètres de pondération ajustables.
            \item Tables de probabilités conditionnelles consultables.
        \end{itemize}
    \item Les choix technologiques (FastAPI + pgmpy côté serveur, React + TypeScript côté client) offrent une base modulaire et testable.
    \item Perspectives :
        \begin{itemize}
            \item Enrichissement des jeux de données de référence.
            \item Confrontation du modèle à des données de terrain.
            \item Ajout d'authentification et de journalisation pour un déploiement en environnement industriel réel.
        \end{itemize}
\end{itemize}
